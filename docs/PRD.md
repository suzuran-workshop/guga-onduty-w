# PRD — 校园值周管理

## 产品目标
用数字化工具体替代传统纸质值周打分表，实现打分→统计→申诉→红旗颁发的全链路管理。
同时为校园信息化大屏提供实时数据源。

## 用户与使用场景
| 用户 | 角色 | 典型场景 |
|------|------|----------|
| 值周生 | duty_student | 巡查校园，在手机上一次选多个班级→多选标签→扣分必拍照→提交 |
| 班主任 | teacher | **不进系统**：钉钉收到扣分推送 → 点免登录链接直接申诉；每周收到得分扣分总计 |
| 德育主任/行政 | admin | 管理年级班级配置、引入组织通讯录并绑定班主任、审核申诉（可调整评分）、人工颁发流动红旗 |
| 来访者/校领导 | guest | 在大屏前查看实时排名和最新记录 |

## 核心问题
1. 纸质打分表易丢失、难汇总
2. 班主任对扣分的异议无规范处理流程
3. 多校区数据不互通，无法统一查看
4. 周排名手工计算费时且易错
5. 校园信息化展示缺少实时数据
6. **班主任不会为了看一条扣分专门登进系统** —— 她们在班级里、手机装着钉钉，
   要求「进系统查看再申诉」的流程等于没有流程，异议只能口头传达、无从留痕

## 功能及其意义
| 功能 | 解决什么 | 为什么需要 |
|------|----------|------------|
| 多标签求和 + 标签分权威 | 替代纸质打分表 | 结构化数据才能自动统计；**分数由所选标签求和，评分环节不得自行改分**（否则统计口径失真、排名可被人为操纵） |
| 班级平铺多选 | 贴合真实巡查节奏 | 值周生站在走廊给一排班级打同一批分，逐个下拉选班级比走路还慢 |
| 自定义值周小组 | 值周安排灵活 | 不同学校/周次值周安排不同 |
| 自定义评价标签和分值 | 评分标准可配置 | 卫生/纪律/两操各校标准不同 |
| 标签模板 | 快速套用常用标签集 | 减少值周生操作步骤 |
| 文字 + 图片记录（**扣分必拍照**） | 提供扣分证据 | 有争议时可回溯；含任一扣分标签则**必须**拍照才能提交 —— 无证据的扣分不该存在 |
| 钉钉推送（扣分即时 + 每周总计） | 班主任**不进系统**也能及时了解 | 减少沟通滞后；扣分推送附**免登录申诉链接**（点开即申诉，一次性 + 限时） |
| 每日小结 | 校内留档与复盘 | 管理员/教师查阅当日概况 |
| 多维度统计排名 | 自动计算周排名 | 替代手工排序 |
| 数据导出CSV | 存档和二次分析 | 对接学校报表系统 |
| 申诉流程（**成立即调分，非撤销**） | 规范异议处理 | 避免扣分争议升级；申诉成立时管理员调整标签集、分数随之重算，记录仍生效并计入统计 —— 只认「全额撤销」会让部分成立的申诉无处表达，管理员只能违心驳回 |
| 流动红旗（**仅管理员人工颁发**） | 班级激励 | 正向反馈机制；系统只按各年级最高分**提供参考**，颁发权归人 —— 自动评选会把「本周该不该颁、颁给谁」的教育判断交给算法 |
| 多校区管理 | 多校区数据隔离 | 各校区独立运行互不干扰 |
| 数字大屏 | 校园信息化展示 | 来访参观和家长会场景 |

## 功能之间的关系
```
配置(校区/年级/班级/标签/模板) → 值周记录(多班级×多标签) → 统计(排名/趋势)
      │                                    ├── 申诉(班主任→管理员，成立即调分)
      │                                    ├── 流动红旗(候选参考→管理员人工颁发)
      │                                    ├── 每日小结(校内留档)
      │                                    └── 数字大屏(实时展示)
      └─ 引入钉钉组织通讯录 → 绑定班主任(钉钉 userid)
                                      ├── 扣分即时推送 ─→ 免登录申诉链接 ─→ 申诉
                                      └── 每周得分扣分总计（进程内定时器 + 管理员可补发）
```

## 范围与非目标
- **范围内**：值周打分、标签管理、统计排名、申诉机制、红旗颁发、多校区、大屏、
  **钉钉集成（组织通讯录同步、工作通知推送、免登录申诉链接、教师周报）**
- **范围外**：学生考勤、课表管理、家校通App、成绩管理、
  **家校通讯录**（钉钉 `dept_id=-7` 子树；按产品要求只引入组织通讯录，且该子树不能用普通部门 API 递归）

> 变更说明（2026-10）：本 PRD 早期把「对接真实推送通道」列为非目标，现已**推翻** ——
> 班主任「不进系统」是需求的核心前提，而该前提只能靠真实推送通道成立。
> 决策依据与实现细节见 `docs/DECISIONS.md` ADR-8。
