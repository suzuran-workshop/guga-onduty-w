# 校园值周应用 — 功能语义对齐分析报告

## 分析日期
2026-10-07（初版）· **2026-10-27 复核并更新**

> ⚠️ 初版分析基于当时的实现。2026-10 的六项需求变更**推翻了其中四条的结论**，
> 已就地更新为当前实现（变更依据见 `DECISIONS.md` **ADR-8**、`PRD.md` 功能表）：
> ① 标签从单选改**多选求和**，且**分数由服务端按标签求和**（评分环节不得改分）；
> ② 扣分**必须拍照**；③ 流动红旗从「自动评选」改**仅管理员人工颁发**（系统只提供候选参考）；
> ④ 申诉通过从「撤销分数」改**调整分数**（记录回 active 照常计分）。
> 另：通知不再是「仅数据记录」——**钉钉真实推送已接入**（扣分即时 + 免登录申诉链接 + 教师周报），
> 班主任**不需要进系统**。图片存储也从文件系统改为 DB 分块后端（ADR-3 已过时）。

## 需求 vs 实现对照表

### 功能描述（10项）

| # | 需求 | 实现情况 | 语义对齐 | 实用性 |
|---|------|---------|---------|--------|
| 1 | 支持通过标签、积分实时记录班级校园表现 | ✅ 完整实现（2026-10 重做）。班级**平铺多选** + 标签 chip **多选 toggle**，records 存 `tagIds` JSON 数组；**score 由 repo 按 tagIds 求和写入**（结构性保证：路由不传 score，故评分模块无法自行改分）；一次提交为**每个班级各落一条独立记录** | ✅ 标签分是唯一权威来源，与「结构化数据才能自动统计」目的一致；旧实现的分数输入框实为语义漏洞（可手填与标签不符的分） | ✅ 贴合真实巡查节奏：站在走廊给一排班级打同一批分 |
| 2 | 支持自定义值周小组 | ✅ duty_groups 表支持创建/编辑值周小组，members JSON 存储成员 user IDs，user.group_id 关联 | ✅ 小组可配置成员，同组用户共享权限 | ✅ 实用 |
| 3 | 支持值周评价标签、分数自定义 | ✅ tags 表支持 campus_id 级别自定义，POST/PUT/DELETE，支持正分/负分/中性三种 category | ✅ 标签名称、分值、颜色均可自定义，按校区隔离 | ✅ 实用 |
| 4 | 支持值周评价标签模板定义 | ✅ templates 表存储 tag_ids JSON 数组，前端 RecordPage 快速模板一键加载 | ✅ 模板预设标签集合，一键套用 | ✅ 实用 |
| 5 | 支持通过文字、图片多种形式记录 | ✅ records 支持 comment（文字）+ images（multipart 或分块预上传 → **DB 分块 storage**，ADR-3 的文件系统方案已过时）；**含任一扣分标签则必须至少一张照片**（前端即时反馈 + 服务端两条上传路径合并后校验，防分块路径绕过） | ✅ 「提供扣分证据、有争议可回溯」由建议升级为**硬性约束**——无证据的扣分不该存在 | ✅ 实用；照片同时是免登录申诉页里教师争辩的依据 |
| 6 | 支持每日值周小结并实时通知相关老师 | ✅ daily_summaries 表 + POST /summaries 创建（校内留档）；**实时通知已接真实通道**：钉钉工作通知 `asyncsend_v2`，扣分即时推送 + 每周得分扣分总计（进程内定时器 + 管理员可补发，`dedupeKey` 幂等） | ✅ 通知不再是数据记录；且**投递终态经 `getsendresult` 回执确认**（`errcode:0` 只代表已受理，发给不存在的 userid 也返 0——不查回执会把失败静默记成成功） | ✅ 班主任无需进系统即可知情 |
| 7 | 支持值周评价推送相关班主任 | ✅ 已实现。`classes.teacherDingtalkId`（**钉钉 userid**，非系统 userId）是班主任绑定的权威，由管理员从「引入组织通讯录」的联系人中下拉指定；扣分推送用 link 类型消息，**附免登录申诉链接**（令牌绑定 recordId + 教师身份 + 过期 + 一次性原子消费，只存 SHA-256） | ✅ 选钉钉 userid 而非系统 userId 是关键取舍：教师**从未登录过系统也能收到推送**，链路零转换 | ✅ 班主任在班级里即可完成「知情 → 申诉」闭环 |
| 8 | 支持自定义时间段统计各班级得分和排名情况 | ✅ statistics/ranking 支持 week + grade_id 筛选，statistics/trend 支持 weeks 参数 | ✅ 周维度排名 + 趋势，支持年级过滤 | ✅ 实用 |
| 9 | 支持值周数据下载，汇总和明细 | ✅ statistics/export 导出 CSV（含班级、年级、标签、分数、周次等全部字段） | ✅ CSV 下载含汇总（ranking）和明细（records） | ✅ 实用 |
| 10 | 支持颁发流动红旗 | ✅ awards 表 + **两步**：`GET /awards/candidates`（只读，算每年级第一名作**参考**，标记本周是否已颁）→ `POST /awards {class_ids}`（管理员勾选后**显式颁发**，幂等靠 UNIQUE + onConflictDoNothing）；管理员可**改选候选之外的班级** | ✅ 语义修正：原「自动评选并直接落库」把「本周该不该颁、颁给谁」的**教育判断交给了算法**；现颁发权归人，系统只提供依据 | ✅ 更贴合实际：最高分未必是本周该表彰的班 |

### 待改进
1. **通知推送**：数据模型已就绪（notified_teachers），但实际推送（WebSocket/短信/邮件）尚未实现
2. **@m3e/react 集成**：当前使用原生 CSS + 自定义组件，未深度使用 @m3e/react 的 Web Component 绑定（因其 API 为 Web Component 封装，与 React 范式需要适配层）
3. **图片查看**：上传已实现，但记录列表中的图片缩略图展示和点击放大需补充
4. **移动端适配**：响应式已做基础处理，移动端导航可改为底部 TabBar
